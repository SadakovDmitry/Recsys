Домашнее задание 1 — персональные top-10 рекомендации¶

Садаков Дмитрий Андреевич, Б05-331

Датасет: UCI Online Retail. Задача — рекомендовать покупателю десять товаров, которые он ещё не покупал. Сравниваются пять самостоятельно реализованных методов: ItemKNN, iALS, EASE, FM с метапризнаками и ALS с собственным целевым сигналом.

Работа содержит код загрузки, EDA, глобальное временное разбиение, подбор на validation, финальное сравнение на test и контрольные эксперименты. Все ячейки выполнены; числа в таблицах получены запуском кода. Реализации находятся в models/.

Из корня репозитория, Python 3.10 или 3.11 (также проверено в текущем Python 3.9):

Обучение работает на CPU; все конфигурации пересчитываются. Готовые таблицы в results/ не подменяют обучение. Для просмотра без Jupyter есть experiments.html.

Seed = 42. До подбора основной метрикой выбрана NDCG@10. Дополнительные: Recall@10, Precision@10 и покрытие каталога. Test не участвует в выборе настроек.

2. EDA и подготовка¶

Удаляем точные дубликаты всех полей, строки без пользователя/товара/времени, отмены (InvoiceNo начинается с C), неположительные Quantity и UnitPrice. Возврат не считается положительной покупкой. Положительную историческую покупку не удаляем задним числом по будущему возврату: это внесло бы будущую информацию.

Оставляем товарные артикулы вида пять цифр + 0–2 буквы. Таким образом исключаются POST, D, M, DOT, BANK CHARGES и другие служебные позиции; правило может исключить нетипичный реальный артикул, что является ограничением очистки. Пропуски названий и страны заменяются UNKNOWN. Никакой случайной подвыборки и фильтрации по будущей активности (например, k-core по всему периоду) нет: используется вся очищенная выборка.

Повторные покупки в разных счетах сохраняем как отдельные события. Для бинарной матрицы X они объединяются в одну пару user–item; для confidence и собственного таргета считаем число различных счетов, а не строк и не купленных единиц.

Наличие длинного хвоста популярности делает персонализацию нетривиальной: популярные товары имеют больше совместных покупок, редкие — меньше обучающего сигнала. Большая разреженность мотивирует регуляризацию ALS/EASE и использование метаданных. Страна сильно несбалансирована, поэтому нельзя ожидать большого эффекта только от неё. Названия и цены могут меняться: признаки фиксируются по истории до соответствующей границы обучения, а не по последнему значению во всём датасете.

3. Протокол оценки¶

  • Train: время строго меньше 01.10.2011.
  • Validation: 01.10.2011 ≤ время < 01.11.2011.
  • Test: время ≥ 01.11.2011, до конца файла 09.12.2011.

Это глобальные календарные границы: события из будущего другого пользователя не попадают в обучение. Настройки выбираются по macro NDCG@10 на validation. Затем все выбранные модели заново обучаются на train+validation, все признаки пересчитываются только по этому периоду, и один раз оцениваются на test.

Кандидаты: весь каталог обучающего периода за вычетом всех уже купленных данным пользователем товаров; отрицательное семплирование при оценке отсутствует. Товары, появившиеся только в held-out периоде, недоступны моделям. Пользователей без обучающей истории исключаем. Также исключаем пользователей без хотя бы одного доступного нового релевантного товара. Числа исключений выводятся явно. Это условная оценка для warm-start; cold-start результатами не покрывается.

Все пять методов и обе абляции на каждом этапе используют один объект данных, один словарь релевантности, один список пользователей и одни маски известных товаров. Если scores совпали, выбирается меньший StockCode в лексикографическом порядке. Наборы пользователей validation и test естественно различаются, но внутри каждого этапа они строго одинаковы для всех методов. Отдельное исключение при <10 кандидатах также общее и учитывается в отчёте.

Метрики, выбранные до подбора¶

Пусть $R_u$ — множество релевантных новых товаров, $L_u$ — упорядоченные 10 рекомендаций, $h_{ur}=\mathbf1[L_{ur}\in R_u]$.

$$\operatorname{Recall@10}(u)=\frac{\sum_{r=1}^{10}h_{ur}}{|R_u|},\qquad \operatorname{Precision@10}(u)=\frac{\sum_{r=1}^{10}h_{ur}}{10}.$$ $$\operatorname{NDCG@10}(u)= \frac{\sum_{r=1}^{10}h_{ur}/\log_2(r+1)} {\sum_{r=1}^{\min(10,|R_u|)}1/\log_2(r+1)}.$$

NDCG@10 — основная: полезные товары должны находиться выше на экране, а нормировка учитывает разное число релевантных объектов. Recall@10: какую долю будущего интереса покупателя удалось покрыть десятью местами. Precision дополняет её долей полезных мест. Для всех трёх берём среднее по пользователям, поэтому активные покупатели не получают большего веса. Coverage@10 — доля каталога, хотя бы раз попавшая в рекомендации; это характеристика разнообразия выдачи между пользователями, а не точности.

4. Модели и подбор настроек¶

В models/ по отдельному файлу на каждый метод. Разрешённые библиотеки используются для матричных операций и autodiff; готовые рекомендательные модели и обучаемые алгоритмы из sklearn/implicit/LightFM/RecBole не используются.

4.1 ItemKNN — коллаборативные соседи товаров¶

Для бинарной матрицы $X$ считаем совместные покупки и сглаженный косинус: $$s_{ij}=\frac{x_i^T x_j}{\|x_i\|_2\|x_j\|_2+\beta},\quad s_{ii}=0.$$ В каждом столбце целевого товара $j$ оставляем $k$ наиболее похожих соседей. Score пользователя: $\hat r_{uj}=\sum_{i:X_{ui}=1}s_{ij}$. Параметр $\beta$ снижает влияние случайных совпадений у редких товаров. Сходство, усечение соседей, scores и top-10 реализованы самостоятельно.

4.2 Базовый iALS¶

$n_{ui}$ — число различных счетов с товаром. Для наблюдавшихся пар $p_{ui}=1$, $c_{ui}=1+\alpha\log(1+n_{ui})$; для остальных $p_{ui}=0,c_{ui}=1$. $$\min_{A,B}\sum_{u,i}c_{ui}(p_{ui}-a_u^Tb_i)^2+ \lambda\left(\sum_u\|a_u\|^2+\sum_i\|b_i\|^2\right).$$ Каждый шаг пользователя решает систему $$\left[B^TB+\sum_{i\in I_u}(c_{ui}-1)b_ib_i^T+\lambda I\right]a_u =\sum_{i\in I_u}c_{ui}p_{ui}b_i.$$ Шаг товаров симметричен. Используем разложение Холецкого; ненаблюдавшиеся пары учитываются через $B^TB$, а не игнорируются. Предсказание $a_u^Tb_i$.

4.3 EASE¶

$$\min_W\|X-XW\|_F^2+\lambda\|W\|_F^2,\quad\operatorname{diag}(W)=0.$$ При $P=(X^TX+\lambda I)^{-1}$ имеем $W_{ij}=-P_{ij}/P_{jj}$ для $i\ne j$, $W_{ii}=0$. Предсказания $XW$. Нулевая диагональ предотвращает прямое копирование входного товара. Обратную матрицу получаем решением системы с единичной правой частью.

4.4 FM с метапризнаками¶

Для разреженного вектора признаков $z$ реализована факторизационная машина второго порядка: $$f(z)=w_0+\sum_j w_jz_j+\frac12\sum_{d=1}^D \left[\left(\sum_jv_{jd}z_j\right)^2-\sum_jv_{jd}^2z_j^2\right].$$ Категориальные признаки кодируются единицами, отсутствующие слова — нулевым padding. Используются user ID, item ID и дополнительные поля:

  1. Последняя известная страна пользователя — возможные различия вкусов и доставки.
  2. Квинтиль исторической медианной цены товара — ценовой сегмент. Границы квинтилей вычисляются по log(1+price) только на обучающем каталоге.
  3. До шести разных слов последнего известного названия товара — тематика и тип товара. Словарь: не более 512 слов длины ≥3, встречающихся хотя бы у трёх товаров train.

Данные будущей покупки (её Quantity, цена конкретной строки, страна из будущей строки) не используются. Нет обучения словаря по validation/test. В refit словарь, цены и страны перестраиваются на train+validation — информации, уже доступной на 01.11.2011.

Обучение: бинарная логистическая функция потерь, Adam, L2-регуляризация параметров (weight decay). Каждая известная пара — положительный пример. На каждую положительную пару в каждой эпохе генерируются 3 равномерных отрицательных товара из неизвестных в обучении этому пользователю. Validation/test не используются даже для исключения ложных negatives. Scores ранжируются без sigmoid, так как она монотонна. Эти scores не интерпретируются как калиброванные вероятности реальной покупки.

4.5 ALS с собственным целевым сигналом¶

Покупки содержат интенсивность и давность интереса. Однако количество единиц может отражать оптовый заказ, поэтому используем число разных счетов, а не Quantity. Пусть $\Delta_{ui}$ — число дней от последней покупки до границы обучения. Определим $$p^{\mathrm{custom}}_{ui}= \left[0.6+0.4\left(1-\exp\left(-\frac{n_{ui}-1}{2}\right)\right)\right] \left[0.5+0.5\exp\left(-\frac{\Delta_{ui}}{90}\right)\right]$$ для известных пар, и 0 для остальных. Первая скобка повышает сигнал повторного интереса с насыщением; вторая ослабляет устаревший интерес, сохраняя половину веса исторического сигнала. Одиночная недавняя покупка даёт примерно 0.6, давняя — примерно 0.3; несколько недавних покупок приближают таргет к 1. Это гипотеза о полезности истории, а не утверждение, что выбранная формула обязательно улучшит качество.

Целевая функция и ALS-шаги те же, но в правой части системы стоит $c_{ui}p^{\mathrm{custom}}_{ui}$. Матрица confidence полностью совпадает с базовой. Следовательно, меняются сами аппроксимируемые значения, а не только веса ошибок. Константы 0.6, 0.4, 0.5, 2 и 90 дней зафиксированы до поиска; 90 дней задают плавный квартальный масштаб забывания. Они не подбираются по test.

Для честного сравнения выполнены: (а) одинаковый поиск ранга и регуляризации у двух ALS; (б) дополнительный CustomALS_matched с теми же выбранными настройками, что у iALS. Контроль FM_ID_only использует выбранные настройки FM и меняет только наличие метаданных. Обе абляции объявлены до просмотра test и не считаются отдельными основными моделями.

Контроль влияния метаданных и собственного таргета¶

FM_ID_only отличается от основной FM только удалением страны, ценового сегмента и слов названия; выбранные rank/epochs/learning rate/negatives совпадают. CustomALS_matched использует настройки, выбранные для базового iALS, поэтому изменение качества в этом сравнении обусловлено изменением целевого сигнала в рамках фиксированной процедуры обучения. Интерпретация и ограничения¶

Кастомный таргет проверяет гипотезу, что устойчивый и недавний интерес полезнее старой одиночной покупки. Если эффект отрицательный, такой способ забывания не поддерживается экспериментом: даже давние покупки могут описывать устойчивые предпочтения, а уменьшение таргетов меняет баланс с фиксированной регуляризацией. Поэтому приведены и одинаковые настройки, и независимый поиск из одной сетки, а утверждение об улучшении делается только по числам выше.

Абляция FM оценивает совокупность трёх типов метаданных. Она не доказывает полезность каждого поля отдельно: для этого нужны отдельные абляции и дополнительные seeds. Отрицательный эффект метаданных может означать шум названий, доминирование UK, ограниченный словарь или недостаточный подбор регуляризации; это гипотезы, а не установленные причины. BCE на обучении не заменяет качество ранжирования.

Ограничения эксперимента:

  • Один магазин и один календарный hold-out. Test включает предрождественский период; это сезонный сдвиг, а его длина отличается от validation.
  • Оценка условна на известных покупателях с новыми покупками из известного каталога. Новые пользователи/товары и повторные покупки не покрываются; их исключения посчитаны.
  • Покупка — не прямое измерение удовлетворённости. Непокупка не обязательно означает неприязнь; нет логов показов и доступности товара на складе. Каталог — товары, замеченные в истории, без проверки актуальных остатков.
  • Фиксированная выдача строится на начало периода и не обновляется внутри периода. Положительные события не отменяются на основании будущих возвратов.
  • Компактная сетка и один seed обучения ограничивают выводы о глобально лучших настройках. Bootstrap по пользователям не измеряет неопределённость обучения.
  • EASE хранит плотную матрицу размера items²; она подходит текущему каталогу, но плохо масштабируется на сотни тысяч товаров. FM оценивает полный каталог пакетами.

Соответствие формулировкам задания¶

Все пять методов реализованы в отдельных .py-файлах models/; обучение и ranking собственные. FM использует метапризнаки, доступные до среза. Пятая модель изменяет именно target при неизменном confidence. У всех методов один протокол релевантности, полный набор кандидатов и один warm-start cohort. Есть NDCG@10 и Recall@10, выполненные ячейки, графики, таблицы поиска и test, инструкции загрузки и запуска, зафиксированные seed, параметры, версии и SHA-256 исходных данных.
